# 新用户全流程测试清单

> 目的：以"全新 Windows 用户"视角验收 Tidy Desktop，覆盖 安装 → 首启 → 导入 → 日常 → 更新 → 卸载 全链路。
> 每次发版前至少完整过一遍 P0；P1/P2 可抽查。
> 修复回归项（⭐ 标记）是历史 bug 的回归验证，必测。
> **§7 是 P2 / P3 新增能力，全部未在真实应用里跑过——发版前必须逐条过。**

---

## 0. 环境准备（模拟新用户）

- [ ] 使用**干净环境**：全新 Windows 虚拟机 / 新建 Windows 本地账户 / 或先卸载应用并删除
      `%APPDATA%\tidy-desktop`（安装版数据目录）与安装目录
      （**便携版**的数据在 exe 同目录的 `data/`，清理时别漏）
- [ ] 记录 Windows 版本与关键设置（后面排查要对照）：
  - 设置 → 辅助功能 → 视觉效果 → **动画效果 开/关**（⭐ 隐身 bug 的触发条件，两种状态都要测）
  - 桌面是否被 OneDrive 重定向（`%USERPROFILE%\OneDrive\Desktop` 存在且非空）
  - 是否中文系统、缩放比例（100% / 125% / 150% 各测一次最佳）
- [ ] 准备素材：桌面放 3~5 个快捷方式（含 1 个 UWP 商店应用、1 个指向中文路径的程序）、
      开始菜单有若干应用；断网/弱网工具（可选，测更新下载）

## 1. 安装阶段（P0）

| # | 操作 | 预期结果 |
|---|---|---|
| 1.1 | 双击 `tidy-desktop-Setup-x.x.x.exe`，UAC 允许 | 安装向导出现，可选安装目录 |

| 1.3 | 安装完成 | 桌面快捷方式 + 开始菜单快捷方式已创建；两者与**任务栏按钮**图标均为「奶油瓷抽屉」 |
| 1.4 | 安装目录检查 | `resources\build\` 下存在 `app-icon.ico` 与 `app-icon-<版本>.ico`；快捷方式图标指向版本化 ICO |

| 1.6 | 安装时勾选"不允许/取消 UAC" | 安装器友好终止，不留半成品 |

## 7. P2 / P3 新增能力（**全部未在真实应用里跑过，发版前必过**）

### 7.1 外观与个性化（P2 / v2.9.5）

- [ ] 自定义背景：纯色与本地图片各设一次；图片可调**模糊**与**暗化**；模态框 / toast 等浮层也一起变（变量写在 `documentElement`）
- [ ] 背景在「图片 ↔ 纯色」之间来回切换：**不串味**（切纯色不该继承图片的暗化值；切图片不该拿到暗化 0 导致亮图糊字）
- [ ] 背景图片文件被移走：自动回退到主题背景，不报错
- [ ] 全局字体族 + 字号缩放（80%~140%）：**只影响文字**，图标尺寸与网格列数不变；搜索窗（独立文档）也生效
- [ ] 分类字号 / 条目高度 / 图标尺寸：在「管理分类」编辑态设置后，分类条与项目网格按各自设置渲染
- [ ] 自定义托盘图标：改完**立即生效无需重启**；保存失败时**不应**刷新托盘（否则"图标换了重启又变回去"）；>32px 自动缩放；文件被删静默回退内置
- [ ] 自动备份：关闭 / 自定义目录 / 保留份数各试一次；目录改动在**下次启动**生效

### 7.2 待办形态（P3-1）

- [ ] 新建文本项目选「待办」：逐条填写、勾选、删除、添加
- [ ] 打开待办卡片：**点勾选框直接落盘**（不必进编辑弹窗）；进度播报；一键清除已完成
- [ ] 笔记 ↔ 待办来回切换：**两边内容都不丢**
- [ ] 「复制内容」导出为 Markdown 任务列表（`- [x]` / `- [ ]`）
- [ ] ⭐ **回归**：新建「文本」与「组合」项目后保存，卡片**必须出现**（曾因必填路径校验被整条丢弃）；重启后仍在

### 7.3 用指定程序打开（P3-2）

- [ ] 给程序/文件夹配 `code --goto <文件>` 这类命令，表单预览与实际执行一致
- [ ] 路径含空格、参数含空格（用双引号）都能正确传递
- [ ] 参数里写 `&`、`|`、`%VAR%`：**只当普通字符**，不触发命令分隔（安全回归）
- [ ] 命令被卸载/挪走后：**不静默回落**到系统默认，给出失败提示
- [ ] 右键「用系统默认方式打开」：**仅配了指定程序时出现**，点它走系统关联

### 7.4 启动参数 / 起始位置（本轮接线）

- [ ] 程序项目填启动参数 + 工作目录 → 启动时确实生效（用一个会回显参数的 exe 验证）
- [ ] 参数里的 `%KEY%` 按环境变量表展开
- [ ] 目标不是 `.exe`（`.lnk` / `.bat` / `.cmd`）时填参数：**被忽略且有提示**，不静默改行为
- [ ] 起始位置填一个**不存在的目录**：应提示"起始位置不对"，而不是"程序启动失败"
- [ ] 以管理员身份启动：参数与起始位置一并带上（PowerShell `Start-Process` 路径）
- [ ] ⭐ **回归**：搜索框里回车打开一个配了「指定程序」的项目，行为应与主界面卡片一致（此前搜索窗忽略 `openWith`）

### 7.5 配置预设导入导出（P3-5）

- [ ] 导出 JSON → 换机器导入：外观 / 搜索引擎 / 快捷命令 / 环境变量 / 浏览器列表 / 自动分类规则都回来
- [ ] 显式导出的**空列表**（如"清空全部环境变量"）导入后确实清空
- [ ] 导入后设置面板各分区显示的是**导入后的值**（不是旧值）
- [ ] 导入非法 / 损坏 JSON：有明确提示，不崩溃
- [ ] 内置搜索引擎：导入后仍存在（`sanitizeConfig` 对 `searchEngines` 取并集，属既有语义）

### 7.6 便携版（R7）

- [ ] 下载 `tidy-desktop-Portable-*.exe` 放进一个**可写**目录（如 U 盘），运行
- [ ] 数据落在 **exe 同目录**的 `data/`，`%APPDATA%` 里**不留任何东西**
- [ ] 整个目录拷到另一台机器：配置、项目、图标缓存都在
- [ ] 「检查更新」：只提供「打开发布页」，**不下载、不安装**
- [ ] ⚠️ 若 exe 所在目录不可写（如 Program Files）：应给出可理解的提示，而不是静默失败

### 7.7 相对路径 / 环境变量（P0-4）

- [ ] 设置便携根目录 + 开启「优先保存相对路径」：新建落在该目录下的项目按相对路径保存；**已有数据不被批量改写**
- [ ] 整个目录搬走后项目仍能启动
- [ ] 环境变量表定义 `%KEY%`：路径 / 启动参数 / 起始位置都能引用
- [ ] 路径去重按**解析后的绝对路径**比较（同一目标不会重复添加）
- [ ] ⭐ **回归**：`shell:AppsFolder\…`（UWP 应用）不被误判成相对路径；Everything 结果（`open-path`）不被解析

### 7.8 本机文件搜索（P1）

- [ ] 装了 Everything 且**开启 HTTP 服务器**：搜索框能搜到本机文件与目录，直接打开

- [ ] 没装 Everything：文件搜索不可用，但应用/命令搜索不受影响
- [ ] 同目录同名文件、多磁盘同名文件：**全部显示**，不互相覆盖
- [ ] 目录结果判定正确（`type === 'folder'` 或 `attributes & 0x10`）

### 7.13 ⭐ 网址 / 商店应用 / 文本项目**不该**被报成「失效」（本轮修复，严重）

> 修复前：这三类项目的"路径"分别存的是网址、`shell:AppsFolder\…` 虚拟目标、空串，
> 而失效检查一律拿它们去查文件是否存在——必然"查不到"。于是整理中心把它们算进
> 「失效」计数，点「一键修复」确认之后**网址和商店应用会被一起删掉**。
> 所以这一节**必须用一个有数据的真实环境跑**，别用空配置。

- [ ] 准备：至少添加 **2 个网址项目**、**1 个商店（UWP）应用**、**1 条笔记**、**1 个待办**、
      1 个组合，再加几个正常的程序 / 文件夹项目
- [ ] ⭐ 打开整理中心（重新扫描）→ 左侧「失效」计数**应为 0**（或只等于真实失效的数量），
      **网址 / 商店应用 / 笔记 / 待办 / 组合一个都不能被算进去**
- [ ] ⭐ 点「一键修复」→ 确认框里"失效项目"的数量与实际失效数量一致；
      确认后**网址、商店应用、笔记、待办、组合全部还在**（这是本节最重要的一条）
- [ ] ⭐ 点「清理失效项」→ 同样只清理真正失效的项目，其余类型不受影响
- [ ] 故意把某个程序项目的 exe 改名 / 移走 → 重新扫描 → **它**应该被算作失效（真失效要认出来）
- [ ] 商店应用双击能正常启动（说明它本来就是有效的，只是没法用"查文件"验证）

### 7.14 ⭐ 失效路径批量重定位（本轮新增）

- [ ] 准备：添加 3~4 个项目，路径形如 `D:\Tools\Alpha\a.exe`、`D:\Tools\Beta\b.exe`，
      并给它们设好**分类、别名、启动参数**（用来验证重定位后这些设置没丢）
- [ ] 在资源管理器里把 `D:\Tools` 整个**移动到** `E:\Backup\Tools`（或改名）
- [ ] 整理中心 → 重新扫描 → 这几个项目被算作失效 → 点「重定位失效项」
- [ ] ⭐ 选择新目录 `E:\Backup\Tools` → 确认框里应显示"找到了 N 个项目"，
      且**目录结构被保留**（`…\Alpha\a.exe`、`…\Beta\b.exe`），不是全堆在根目录下
- [ ] 确认后：卡片能正常启动，**分类 / 别名 / 启动参数 / 待办都还在**（重定位的价值就在这里）
- [ ] ⭐ 故意选一个**错误的**目录 → 应提示"未找到匹配的项目"，**不做任何修改**
- [ ] ⭐ 制造"部分命中"：只把其中一个文件也一起挪走，其余留在原处 →
      应出现三选一（更新并移除未找到 / 只更新 / 取消），
      - 选「只更新」→ 未找到的项目**保留**，之后可以再试一次重定位
      - 选「更新并移除」→ 未找到的项目被移除
      - 选「取消」→ **什么都不发生**（一个项目都不改）
- [ ] 重定位后撤销（Ctrl+Z / 撤销入口）能回到重定位前的状态
- [ ] 网址 / Steam / 商店应用 / 笔记 / 待办 在这套流程里**不会**被当成可重定位对象

### 7.15 ⭐ 从收纳格移出卡片（本轮新增）

- [ ] 建一个收纳格 → 把一张卡片拖进去 → 卡片只在收纳格里出现一份
- [ ] ⭐ 在**收纳格内**的卡片上点右键 → 菜单里有「移出收纳格」（鼠标悬停时提示里带格子名）
- [ ] 点它 → 卡片从收纳格消失、**回到它本来所属的分类网格里**（分类归属没变）
- [ ] 在**不在收纳格里**的卡片上点右键 → 菜单里**没有**「移出收纳格」
- [ ] 移出后再点一次卡片，能正常启动（数据没被改坏）

### 7.16 ⭐ 按热键唤出的响应速度（本轮优化，需在**真机**上感受）

> 这几条都是"手感"项，没有自动化断言，只能人眼+秒表。测之前先确认自己的网络环境：
> **中国大陆网络**下第 1 条才有意义（`fonts.googleapis.com` 不可达才是瓶颈前提）。

- [ ] ⭐ **首帧不再白屏**：断开外网（或挂着会超时的代理），按热键唤出主窗口 ——
      窗口应当在几十~一两百毫秒内画出内容（先看到系统字体的界面）。
      **不该**出现"窗口框出来了、里面一片空白，等几秒才出字"。
- [ ] ⭐ **搜索框唤出无跳变**：搜一个有很多结果的词（比如 `a`）让窗口变高 →
      Esc / 点别处把它藏起来 → 再按热键唤出 ——
      窗口应当**直接就是空的、矮的**。**不该**先闪一帧上次的结果再缩回去。
- [ ] ⭐ **搜索框唤出能立刻打字**：唤出后马上敲键盘，字符不会丢（输入框已聚焦）。
- [ ] ⭐ **搜索框字体与主界面一致**：两边都是同一套字体（此前搜索框一直退回系统字体）。
- [ ] ⭐ **关联文件夹挂在慢盘上时唤出主窗口不卡**：
      把一个关联文件夹指向离线网络盘 / 休眠的外置盘（或一个层级很深的目录），
      然后按热键唤出主窗口 —— 窗口应当立刻可用（能点、能滚、能切分类），
      扫盘在后台慢慢跑完后再刷新列表。
- [ ] **频繁 alt-tab 不重复扫盘**：反复切出去再切回来十几次，
      主进程 CPU 不应持续占用（触发侧有 1.2s 延迟 + 30s 最小间隔两道闸）。
- [ ] **冷启动窗口先出现**：把 `apps.json` 撑大（导入几百个项目）后冷启动 ——
      窗口出现的时间不应明显变长（备份已挪到窗口创建之后并行执行）。

## 8. 已知风险点（未完全修复，测试时重点关注并记录表现）

1. **Gitee 渠道为空**：国内用户更新只能走 GitHub 下载（91MB），弱网/校园网易失败——补发 Gitee Release 前此风险一直在。
2. **GitHub API 限流**：未认证 60 次/小时/IP，校园网出口共享时可能触发。
3. **图标待补全**：部分目标（MSI 缓存、无图标 exe）提取失败属预期，但"待补全"徽标需要给出用户可理解的解释/操作。
4. **全局热键冲突**：用户可设 `Ctrl+A` 等高频键为全局热键，会干扰所有应用的"全选"，当前无冲突警告。
