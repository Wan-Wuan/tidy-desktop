# 新用户全流程测试清单

> 目的：以"全新 Windows 用户"视角验收 Tidy Desktop，覆盖 安装 → 首启 → 导入 → 日常 → 更新 → 卸载 全链路。
> 每次发版前至少完整过一遍 P0；P1/P2 可抽查。
> 修复回归项（⭐ 标记）是历史 bug 的回归验证，必测。

---

## 0. 环境准备（模拟新用户）

- [ ] 使用**干净环境**：全新 Windows 虚拟机 / 新建 Windows 本地账户 / 或先卸载应用并删除
      `%APPDATA%\tidy-desktop`（数据目录）与安装目录
- [ ] 记录 Windows 版本与关键设置（后面排查要对照）：
  - 设置 → 辅助功能 → 视觉效果 → **动画效果 开/关**（⭐ 隐身 bug 的触发条件，两种状态都要测）
  - 桌面是否被 OneDrive 重定向（`%USERPROFILE%\OneDrive\Desktop` 存在且非空）
  - 是否中文系统、缩放比例（100% / 125% / 150% 各测一次最佳）
- [ ] 准备素材：桌面放 3~5 个快捷方式（含 1 个 UWP 商店应用、1 个指向中文路径的程序）、
      开始菜单有若干应用；断网/弱网工具（可选，测更新下载）

## 1. 安装阶段（P0）

| # | 操作 | 预期结果 |
|---|---|---|
| 1.1 | 双击 `tidy-desktop-Setup-x.x.x.exe`，UAC 允许 | 安装向导出现，可选安装目录 |
| 1.2 | **应用正在运行时**再次运行安装包（先启动旧版、托盘常驻，再装新版）⭐ | 安装器自动结束运行中的应用并完成安装，**不得出现"安装没有完成"** |
| 1.3 | 安装完成 | 桌面快捷方式 + 开始菜单快捷方式已创建；两者与**任务栏按钮**图标均为「奶油瓷抽屉」 |
| 1.4 | 安装目录检查 | `resources\build\` 下存在 `app-icon.ico` 与 `app-icon-<版本>.ico`；快捷方式图标指向版本化 ICO |
| 1.5 | 安装完成后应用自动启动（或手动启动） | 主窗口出现；**任务栏按钮图标 = 应用图标**（⭐ AUMID/图标一致性回归） |
| 1.6 | 安装时勾选"不允许/取消 UAC" | 安装器友好终止，不留半成品 |

## 2. 首次启动（P0）

| # | 操作 | 预期结果 |
|---|---|---|
| 2.1 | 首启 | 出现引导页（onboarding）；`%APPDATA%\tidy-desktop\data\` 自动创建 |
| 2.2 | 引导完成 | 进入主窗口；空状态提示"点击「添加应用」或「添加文件夹」" |
| 2.3 | 托盘图标 | 出现且为应用图标；双击可显示/隐藏主窗口 |
| 2.4 | 默认热键 | `Alt+Space` 呼出主窗口、`Ctrl+K` 呼出搜索；再次按隐藏 |
| 2.5 | 关闭主窗口（点 X） | 首次最小化到托盘时收到一条系统通知"Tidy Desktop 仍在运行"（仅一次）；进程仍在、任务栏按钮消失 |
| 2.6 | **动画效果=关** 的机器上重复 2.2 与导入 ⭐ | 卡片**直接静态显示**，不得出现网格空白/卡片隐身（隐身 bug 回归） |

## 3. 导入快捷方式（P0）

| # | 操作 | 预期结果 |
|---|---|---|
| 3.1 | 引导页/管理页选择导入桌面快捷方式 | 扫描出桌面+开始菜单的 .lnk，去重（同一程序多 lnk 只留一条） |
| 3.2 | OneDrive 重定向桌面的机器 | 桌面快捷方式能被扫到且**不重复**（重定向路径与本地 Desktop 去重） |
| 3.3 | 导入完成 | 卡片全部显示（含图标）；分类"桌面快捷方式/开始菜单"自动建立 |
| 3.4 | 图标检查 | 绝大多数卡片有图标；个别无图标的进入"N 个图标待补全"并有补全动作，**卡片仍显示**（占位图标） |
| 3.5 | 指向特殊目标的 lnk | MSI 缓存路径（`C:\WINDOWS\Installer\{...}`）、已卸载程序、UWP 应用——导入不崩溃，启动失败有提示 |
| 3.6 | 双击卡片启动 | 目标程序正常拉起；启动计数 +1 |
| 3.7 | 搜索启动 | `Ctrl+K` 输入名称/拼音/别名能搜到并启动 |
| 3.8 | 数量边界 | 快捷方式极多（>600 个 lnk）时导入有上限不卡死 |
| 3.9 | 动画效果=关 ⭐ | 导入后网格立即可见全部卡片（隐身 bug 回归） |

## 4. 日常使用（P1）

- [ ] 拖拽排序、拖入新 .lnk 到窗口、右键菜单（编辑/删除/隐藏/移动分类）
- [ ] 新建分类/子分类并移动应用；重启应用后顺序、分类、配置保持
- [ ] 设置：主题切换、卡片尺寸/列数、搜索设置；关闭设置立即生效
- [ ] 开机自启开关：开启后 `任务管理器 → 启动` 出现 tidy-desktop 且生效
- [ ] 热键冲突：把主热键改为 `Ctrl+A` 这类全局高频键，确认有冲突提示（当前可能没有，属于体验项）
- [ ] 多显示器/缩放：150% 缩放下窗口与搜索框位置正常，重开后位置不漂移出屏幕
- [ ] 备份/恢复：导出备份 JSON → 清空数据 → 导入恢复，卡片与分类完整

## 5. 更新（P0，⭐ 两项回归）

| # | 操作 | 预期结果 |
|---|---|---|
| 5.1 | 设置/关于 → 检查更新（有新版本时） | 提示新版本 + 发布说明；**下载走 Gitee 优先**（当前 Gitee 空，走 GitHub 时进度正常） |
| 5.2 | 下载完成 → 安装 ⭐ | 应用自动退出 → 安装器等待进程真正退出 → 静默安装 → 应用重启为新版本；**不得报"安装没有完成"** |
| 5.3 | 应用运行中手动双击新安装包 ⭐ | 安装器自动结束托盘中的应用并完成安装（customCheckAppRunning 回归） |
| 5.4 | 断网时检查更新 | 提示检查失败，不崩溃、可重试 |
| 5.5 | GitHub API 限流（同一出口 IP 高频） | 提示 rate limit 而非静默无更新 |
| 5.6 | 更新中断（下载中杀进程） | 重新检查更新可续传/重下，SHA256 校验保证不装损坏包 |

## 6. 卸载（P1）

- [ ] 从"设置 → 应用"卸载：安装目录、桌面/开始菜单快捷方式被清理；`%APPDATA%\tidy-desktop` 用户数据保留（重装不丢数据，属预期）
- [ ] 卸载时应用正在运行：进程被结束、卸载成功
- [ ] 卸载后重装旧版本：数据完整恢复

## 7. 已知风险点（未完全修复，测试时重点关注并记录表现）

1. **Gitee 渠道为空**：国内用户更新只能走 GitHub 下载（91MB），弱网/校园网易失败——补发 Gitee Release 前此风险一直在。
2. **GitHub API 限流**：未认证 60 次/小时/IP，校园网出口共享时可能触发。
3. **图标待补全**：部分目标（MSI 缓存、无图标 exe）提取失败属预期，但"待补全"徽标需要给出用户可理解的解释/操作。
4. **全局热键冲突**：用户可设 `Ctrl+A` 等高频键为全局热键，会干扰所有应用的"全选"，当前无冲突警告。
5. **开始菜单导入质量**：可能导入卸载器/帮助文档类 lnk（如 WeChatAppLauncher 被误名为其他应用），属导入过滤策略问题。
